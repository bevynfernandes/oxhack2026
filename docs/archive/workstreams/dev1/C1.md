## Consumer interfaces

- `catalog.schemas.CatalogSnapshot`: normalized organizations, products,
  packages, stable repository IDs, dated evidence and effective mappings.
- `storage.contracts.ObservationSeries` / `ObservationRevision`: integer daily
  counts with separate measurement, publication, assumption and collection times.
- `SourceCoverage`: complete/partial/missing days, never inferred zero-fill.
- `DatasetManifest`: exact catalogue/mapping versions, extraction/filter/policy
  provenance, feature/target definition versions and hashed artifact references.
- `ArtifactStore`, `DatasetReader`, `DatasetPublisher`: protocols only. Imports
  do not initialize clients, databases, credentials, network calls or models.

Dev 2 maps `dataset_version`, `mapping_version`, `package_id`, `tool_id` and
`organization_id` directly into C2 identity. `source_revision_ids` refer to
C1 `revision_id`. Dev 3 reads catalogue fields and public coverage summaries;
its repository adapter will map C1/C2 into C3 DTOs.

PR #9 review follow-ups: series units are fixed by source (npm/PyPI downloads,
GitHub events, Hacker News mentions). `DatasetReader.series(dataset_version)`
provides typed identities for package-to-series resolution without exposing the
storage format. Publication reads and exact history-vintage selection remain

`ArtifactReference` is the data-layer canonical type: relative POSIX path,

Dev 2 should reconcile it after C1 review. No model or API contract was edited
to force compatibility in this checkpoint.

## Availability and revisions

All intervals are half-open UTC; each observation is one midnight-to-midnight
day. Complete counts include real zero. Missing counts are null. Partial counts
are explicitly partial and must not enter complete-history features or labels.

`published_at` is actual vendor evidence, otherwise null. Under `assumed_lag`,
`assumed_available_at` is a separate project assumption and `available_at` equals
that bound. `validate_observation_policy` checks the exact pinned lag. Under
`vendor_published` or `collected`, `available_at` equals the corresponding real
timestamp. `first_collected_at` and `retrieved_at` always retain actual collection.

Reconstructed reads may use an explicitly documented lag policy and must disclose
retrospective revisions. Prospective reads additionally require `collected_by`
at the cutoff. A historical revision retrieved today must never become a fact
actually collected years ago. `ObservationQuery` can apply both knowledge-time
filters; it returns all matching frozen revisions, never silently substitutes
current vendor values. Dev 2 selects the eligible vintage for its experiment.

`revision_id` is immutable. Changed counts create new revisions and may identify
`supersedes_revision_id`; prior dataset manifests continue to identify the old
revision set. The storage implementation will verify foreign keys, source policy,
checksums and coverage before publication; Pydantic types alone cannot prove a
bundle's completeness or that an artifact exists.

## Identity and schema compatibility

Primary package and organization-representative mappings cannot overlap within
an ecosystem. Adjacent effective intervals are allowed; changing packages creates
a new identity/series. Repository names may change while their numeric ID remains.
Current-catalogue reconstruction explicitly retains survivorship limitations.
Historical membership additionally requires dated eligibility and evidence.

Exports under `contracts/datasets/data/` use `data-v1`; saved drift tests compare
them with the Python models. Breaking changes after review need a new version.
JSON nullability follows these schemas. Planned Parquet encoding is String for
IDs/enums, Int64 for counts, Datetime(us, UTC) for instants, Boolean for flags,
Struct for windows/references and List for tuples. No datetime/array JSON is
stored as a text column. Arrow round-trip tests accompany the later writer.

Small fixtures in `tests/fixtures/data/` are explicitly synthetic, including
placeholder hashes. They cover zero/missing/partial/late/revised observations,
package migration and repository rename. They are not a real artifact handoff.
